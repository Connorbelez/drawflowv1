# Traceability Matrices for DrawFlow

This document provides comprehensive traceability mappings between the requirements, use cases, and user flows defined in the DrawFlow PRD and the verticals that implement them.  Each matrix lists the corresponding vertical(s) and the automated tests that verify the functionality.  Test identifiers follow the convention `VBxxxx – it <test description>`, where `xxxx` is a unique number.  End‑to‑end (E2E) tests ensure that user flows behave as expected, and unit/integration tests cover alternate paths and failure conditions.

## User Flows Traceability Matrix

|---|---|---|
| **Login and organisation selection:** User navigates to `/login`, authenticates via WorkOS, is redirected to select their organisation if multiple, and lands on the `/app/:orgSlug/home` page. | 01 | VB0101 – ensures login flow and tenant selection redirect; VB0102 – guards protect the app when unauthenticated. |
| **Proposal editing flow:** Builder opens the proposal editor, enters build details, creates milestones, drags Gantt bars, enters working‑capital, requests plan alternatives, reviews cost summary, selects a plan, uploads documents, and submits the proposal. | 02, 03 | VB0201, VB0202, VB0204, VB0207, VB0208, VB0209. |
| **Admin review flow:** Admin opens a submitted proposal, reviews milestones and warnings, examines plan comparisons and cost breakdown, requests changes or approves the proposal, creating an active build. | 02 | VB0210, VB0211. |
| **Active build update flow:** Builder accesses the Build Workspace, updates progress by adjusting forecast dates or starting/completing milestones, sees schedule health indicators, warnings, running cost summary, and claims completion when ready. | 04, 10, 05 | VB0401, VB0402, VB0403, VB0405, VB1001, VB1002, VB0502, VB0503. |
| **Completion claim flow:** Builder opens the claim form (either from workspace or dedicated route), selects the milestone, uploads evidence via camera or file picker, confirms geofence capture, enters incurred cost and optional lower draw amount, submits the claim, and sees it in history. | 05 | VB0502, VB0503, VB0504, VB0505. |
| **Verification flow:** Verifier (with permission) opens the claim review screen, reviews evidence and geofence status, requests more info or a site visit if needed, receives the site visit submission, and approves or rejects the claim.  Site visit orders can be placed during this flow, and portal‑visible flags are set on site visit assets. | 06 | VB0601, VB0602, VB0603, VB0604, VB0606, VB0607, VB0608. |

| **Site visit report flow (offline):** Inspector opens the PWA site visit report on a mobile device, captures photos/videos/notes offline, marks certain assets as portal‑visible, syncs when online, and submits the report. | 06 | VB0607 – offline report capture and sync; VB0605 – portal visibility. |

| **Webhook subscription flow:** External system registers a webhook endpoint via the admin UI, subscribes to events, verifies the secret signature on incoming events, and handles retries on failure. | 09 | VB0905, VB0906. |
| **MIC portal consumption flow:** MIC portal authenticates with API key, fetches the workspace projection, milestones, draw releases, and portal‑visible evidence; uses external IDs to map records; and listens for webhook events to refresh its view. | 09 | VB0902, VB0903, VB0904, VB0905. |

| **Chat flow:** Users open the chat panel for a build or entity, post messages, attach files, and (optionally) promote attachments to evidence; chat does not trigger any domain transitions. | 11, 05 | VB1109, VB1110, VB1111, VB0505 (promotion to evidence). |
